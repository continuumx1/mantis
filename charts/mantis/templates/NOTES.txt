Mantis is deployed.

1. Reach the UI:
{{- if .Values.web.ingress.enabled }}
{{- range .Values.web.ingress.hosts }}
   http{{ if $.Values.web.ingress.tls }}s{{ end }}://{{ .host }}
{{- end }}
{{- else if eq .Values.web.service.type "LoadBalancer" }}
   Run:
     kubectl get svc {{ include "mantis.web.fullname" . }} -n {{ .Release.Namespace }} -w
   and use the EXTERNAL-IP once it's assigned.
{{- else if eq .Values.web.service.type "NodePort" }}
   Run:
     kubectl get svc {{ include "mantis.web.fullname" . }} -n {{ .Release.Namespace }}
   and use <any-node-ip>:<the-listed-NodePort>.
{{- else }}
   No Ingress and a ClusterIP Service means nothing outside the cluster
   can reach it yet. For local access:
     kubectl port-forward -n {{ .Release.Namespace }} svc/{{ include "mantis.web.fullname" . }} 8081:{{ .Values.web.service.port }}
   then open http://localhost:8081
{{- end }}

2. Sign in.
   This is a Public Preview build: the login screen shows a demo
   credential (admin/admin) right on the screen. That gate is not real
   authentication — see the repo's docs/USER_GUIDE.md ("Public Preview
   notes") before pointing this release at anything beyond your own
   machine or team.

3. Verify it's actually reading your cluster:
     kubectl get pods -n {{ .Release.Namespace }} -l app.kubernetes.io/instance={{ .Release.Name }}
   Both Pods should be Running; mantis-engine's logs will name the
   cluster context it connected to.

By default this pulls {{ include "mantis.engine.image" . }} and
{{ include "mantis.web.image" . }} straight from Docker Hub — no local
build needed. If you're running your own build instead (see
build/Dockerfile.engine and build/Dockerfile.web), point image.repository
at it, or load it directly into a local cluster (e.g.
`minikube image load mantis-engine:dev`) and set image.pullPolicy to
"Never".
